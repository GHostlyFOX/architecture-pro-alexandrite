# Выбор и настройка мониторинга в системе

## Мотивация

Внедрение мониторинга позволит компании значительно увеличить прозрачность процессов в ИТ-системах компании. Для компании это приведет к следующим преимуществам:

1. Проблемы в работе системы будут решаться быстрее, и у команды будет больше времени на внедрение новых фич
2. Снизится количество ошибок, блокирующих релиз, что позволит быстрее доставлять фичи до клиентов
3. Уровень недовольства клиентов значительно снизится, если компания будет быстрее решать их проблемы, что снизит финансовые потери
4. Потенциально с помощью мониторинга бизнес может получить ценные бизнес-инсайты, что позволит более обоснованно принимать стратегические решения

## Выбор подхода к мониторингу

В зависимости от характера сервиса или компонента выбираются разные похдоды к мониторингу:

1. **USE** - для нагруженных сильно ресурсов, производительность которого снизилась с ростом нагрузки
   2. *Очереди сообщений*
2. **Четыре золотых сигнала** - для частей системы, связанных с предоставлением API
   1. *API (Shop, CRM, MES)*
3. **RED** - для сервисов, управляемых запросами (либо к БД, либо отправлением сообщения в очередь)
   1. *Базы данных и файловое хранилище*

## Выбор метрик

1. Для очередей сообщений
    * Number of message `in-flight` in RabbitMQ (метки: `queue_name`)
    * Number of `dead-letter-exchange` letters in RabbitMQ (метки: `queue_name`)
2. Для всех видов API
    * Response time (latency) for API (метки: `service`, `instance`, `method`, `path`)
    * Kb transferred (received) for API; Kb provided (sent) for API (метки: `service`, `instance`, `method`, `path`, `status`)
    * Number of `HTTP 500` responses (метки: `service`, `instance`, `method`, `path`, `status`)
    * Number of requests (RPS) for API (метки: `service`, `instance`, `method`, `path`, `status`)
3. Для базы данных и файлового хранилища
    * Number of queries for DB instance (метки: `db`, `instance`, `type`, `status`)
    * Number of errors for DB instance (метки: `db`, `instance`, `type`, `error_type`)
    * DB query duration (метки: `db`, `instance`, `type`)

## План действий

Для внедрения мониторинга нужно выполнить следующие шаги:

1. Собрать список библиотек и фреймворков для подключения сервисов, БД и очередей к Prometheus
2. Развернуть инстансы Prometheus с time-series БД и Grafana
3. Настроить подключение от сервисов к экспортерам Prometheus
4. Создать и настроить требуемые дэшборды и графики в Grafana
5. Настроить алертинг в случае превышения целевых порогов ошибок или повышенной утилизации
